# Human Blockchain One-Prompt Commissioning Package

**Package status:** Working commissioning baseline; no agent runtime, persistent worker, external connector, or consequential autonomy is activated by this documentation.

## Purpose

This is the single-folder package used to orient and commission a fresh, repository-connected Human Blockchain delivery team. It turns the documented intent into a reproducible operating sequence: load the correct evidence, identify the active authority context, select a bounded mission, activate only the required team cells, produce reviewable artifacts, obtain human decisions, and write learning back into the appropriate knowledge records.

The package does **not** replace the Human Blockchain Operating System repository. That repository remains the source-grounded knowledge library. This package is the executable operating wrapper around it. Its purpose is to eliminate repeated oral reconstruction without turning historical drafts or agent outputs into controlling policy.

## Start here

1. Read `00-one-prompt-event.md` and complete its preflight before delegating any work.
2. Use `01-authority-and-source-load.md` to establish the active decision authority, source hierarchy, and approved retrieval boundary.
3. Select only the necessary profiles in `02-agent-team-catalog.md`; a profile is not an automatically active agent.
4. Create one mission record using `03-mission-and-artifact-contracts.md`.
5. Operate the handoffs in `04-orchestration-contracts.md`, observe the tool/data restrictions in `05-permission-and-data-boundaries.md`, and stop at the gates in `06-human-gates-and-escalation.md`.
6. Complete the readiness and clean-clone materials in `07-readiness-and-improvement.md` before treating the package as activated.

## Source and proposal discipline

This package uses four labels:

| Label | Meaning |
|---|---|
| **Source-grounded** | Directly supported by an identified Human Blockchain source path and commit. |
| **Implemented** | Present in the DH Mission Control application and testable now. |
| **Proposed** | A recommended operating design requiring founder approval before activation. |
| **Open decision** | A material choice intentionally not settled by source material or current implementation. |

The Human Blockchain sources establish that the goal is a continuously improving system, that agents assist rather than replace accountable humans, that each Company Admin can have a bounded supporting agent, and that the first agent prompt and first agent set are open questions. [1] [2] [3]
