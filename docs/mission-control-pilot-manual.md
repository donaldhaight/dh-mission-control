# DH Manus Operating System Mission Control Pilot

## Preface

This internal application is the **synthetic-only control plane** for the DH Manus Operating System. Its purpose is to make the founder’s work visible and governable: stack readiness, experiments, risks, decision gates, source-grounded context, bounded agent work, evidence, review, and the next required action are represented as auditable operational records.

The first release is not a production claims, financial, legal, communications, or deployment system. It demonstrates the system architecture using clearly labeled synthetic records. It creates drafts and review-ready packets, but it never promotes consequential state or performs an external action without an authorized human decision.

## Operating Principles

| Principle | Pilot rule |
|---|---|
| Synthetic-only by default | Every work item and artifact is tagged `synthetic_only`; live financial, regulated, external-communication, and production-access actions are blocked. |
| Explicit authority | Protected actions display and validate organization, legal entity, stakeholder group, and role context. |
| Source before proposal | Context packs may contain only allowlisted Human Blockchain repository paths; source status and new proposals are separately labeled. |
| Evidence before promotion | Drafts require citations, independent reviews, and a named human gate before a consequential status transition can occur. |
| Auditability by design | Retrieval, assumptions, drafts, reviews, decisions, notifications, and improvement candidates record a correlation trail. |
| Reversible improvement | Automation and agent changes are tracked as improvement candidates and remain disabled until reviewed. |

## Pilot Scope

The pilot demonstrates a single synthetic **Lead → Task → Evidence → Review → Founder Decision** flow. Its required artifacts are a mission record, a context pack, a bounded work item, a source-cited draft, an independent review, a decision gate, evidence references, an evaluation record, and an audit trail.

The dashboard provides an internal operating view, not a public product experience. It uses the platform’s authenticated user and server-protected procedures. The initial entity context is intentionally synthetic and labels itself as such in every protected workspace.

## Domain Glossary

| Term | Meaning in this pilot |
|---|---|
| Active context | The organization, legal entity, stakeholder group, and role under which an authenticated internal user is viewing or acting. |
| Mission | A bounded outcome with an accountable owner, success measure, risk profile, work graph, and decision gate. |
| Context pack | A reviewed, allowlisted set of repository paths used to ground a mission or agent work item. |
| Artifact contract | The required input, output, citation, review, and non-action constraints for a work item. |
| Independent review | A review performed by a separate team record or human role before a high-impact draft advances. |
| Decision gate | A named human action to approve, reject, defer, or request revision of a decision-ready packet. |
| Improvement candidate | A proposed change to a skill, agent, workflow, policy, or automation that remains unpromoted until evaluated and approved. |

## Acceptance Criteria

The pilot is complete only when an authenticated user can view the active context, inspect dashboard readiness and founder action, navigate the requirements register, manage synthetic missions/work items, assemble an approved source pack, upload a provenance-linked reference, generate a structured cited draft and review record, record a human decision, and trace those actions in the audit ledger. Server validation must reject live/consequential pilot actions and unapproved repository paths.

## Change Control

Material changes to authorization, data classification, source allowlisting, agent capability, automation behavior, external integration, or deployment ownership require a requirements update and a linked architecture delta. The first deployment must retain synthetic-only enforcement regardless of client-side UI state.
