# Commissioning Package Snapshot and Index

**Status:** Implemented documentation package; runtime activation remains a proposed, gated next step.

## Why this file is in the open knowledge bundle

The open knowledge bundle must remain self-contained. It therefore does not depend on a link outside this folder. This file preserves the essential commissioning design so a fresh reader can understand the activation model from this bundle alone. A separate, reusable `docs/commissioning-package/` folder exists in the application repository for connected working teams; it elaborates the same model and should be used only after source, authority, and activation checks are complete.

## Commissioning model

The One Prompt Event is not a command to let an unrestricted agent act. It is a reproducible startup sequence:

1. Load the required Human Blockchain source records, current decisions, risks, glossary, roadmap, relevant requirements, and QA material.
2. Establish active actor, stakeholder group, legal entity, human role, permission, agreement/SLA, source pack, data class, reviewer, and human decision owner.
3. Select the smallest purpose-led group of profiles needed for one bounded mission.
4. Assign each profile a work packet with allowed sources/tools, output, reviewer, handoff, stop condition, and no shared write target.
5. Produce source-cited artifacts, then require independent review against evidence, authority, safety, and acceptance criteria.
6. Stop at a named human gate before promotion, deployment, external action, money, ownership, legal/regulated action, public claim, or production permission change.
7. Record the decision, observed result, evaluation, source/provenance, affected requirement/QA/open-question records, and controlled improvement candidates.

## Non-negotiable boundary

Agents assist; humans remain accountable. An agent may prepare, retrieve, monitor, draft, recommend, test, and explain within an approved work packet. It may not independently bind an entity, accept an offer, move money, grant authority, make insurance/coverage/legal/tax decisions, change protected permissions, publish external claims, or activate production operations. These boundaries are grounded in the Human Blockchain continuity brief and agent instructions. [1] [2]
